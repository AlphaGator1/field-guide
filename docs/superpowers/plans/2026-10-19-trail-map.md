# Trail Map Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the trail map (systems as hills, groups as regions, connections as trails, flows as walkable routes) to the page `guide render` writes, for any project, plus a read-only mode that draws it for a guide-shaped JSON the CLI does not manage.

**Architecture:** The CLI measures each system's code (footprint: non-blank code lines; height: branch points) and lays the hills out deterministically at render time, then ships both in the page's JSON. A self-contained map module (`templates/map.html`, a `<style>` plus `<script>` fragment) is inlined into the existing page template at a marker; it draws terrain, trails and routes in SVG and talks to the page through a small `TrailMap.mount` API. `render` gains flags for a map-only page and for an outside guide JSON.

**Tech Stack:** TypeScript (src/, bundled by esbuild into one file `dist/guide.mjs`), plain ES5-style browser script and SVG in the template, Node's own `test/run.mjs` (black-box: it runs the bundled CLI in temp git repos).

**Spec:** `docs/superpowers/specs/2026-10-19-trail-map-design.md`. Read it first; this plan does not repeat its reasoning.

## Global Constraints

- The CLI stays dependency-free: local files and `git` only, no network (CLAUDE.md).
- The page stays one self-contained file: system fonts, inline script and style only, no `http(s)` `src`/`href`, light and dark, works from 375px wide up.
- `dist/guide.mjs` is rebuilt with `npm run build`, never edited; `npm run check` passes before every commit.
- Every new file is claimed in `docs/field-guide/guide.json`; entries whose behaviour changes get their sentences fixed in the same commit.
- `render` never changes `guide.json`; with `--guide` it writes only the named output file.
- No new subcommand (a project may have a system with that id): everything is flags on `render`.
- The template's script idiom is ES5 (`var`, `function`, no arrow functions or classes); the map module follows it.
- Same guide and same code sizes give identical positions; a size change within one bucket moves nothing.
- Performance: render of a 60-system guide under 2 s in the test; the page's first draw under 300 ms for 60 systems (checked by hand in a browser).
- Commits: `git commit -F <file>`, explicit paths, no person named, end with the `Co-Authored-By` line the session uses. No push and no version bump: the owner releases.

## Review Focus

1. **CRLF files** (Windows checkouts): a line holding only `\r` is blank, and counts match the LF version. Test in Task 1.
2. **Huge or unreadable files** (a 3 MB file, a file deleted between listing and reading): skipped, render still succeeds. Test in Task 1.
3. **Degenerate guides** (one system, no connects, no flows, a group with one system, a system whose `group` is not in `groups`): render succeeds and every position is a finite number. Test in Task 2.
4. **Hostile names** (a system name containing `<b>` or `</script>`): reaches the page escaped and is drawn with `textContent`, never `innerHTML`. Test in Task 4 (data side) and the module uses `textContent` only.
5. **Walk mode** (`"files": "walk"`, no git): sizes still computed, the generated-file check is skipped without error. Test in Task 1.

The branch rule (copy exactly; it is the spec's rule plus a guard so `.match(` and `obj.case` do not count):

```ts
const BRANCH = /(?<![.$\w])(?:if|elif|for|foreach|while|case|catch|except|when|match)\b|&&|\|\||\s\?\s/g
```

Minified: any line longer than 3,000 characters, or an average non-blank line longer than 250 characters over at least 5 lines. Binary: a NUL in the first 8,000 bytes. Read with the existing `readText(root, rel)` (2 MB cap): `undefined` means skip.

### Task 2: Lay out the hills, stable as code changes

**Files:**
- Create: `src/layout.ts`
- Modify: `src/types.ts` (add `Hill`), `src/render.ts` (`map.hills` replaces `map.sizes`), `docs/field-guide/guide.json`
- Test: `test/run.mjs` (section `4c. trail map: layout`)

**Interfaces:**
- Consumes: `Size`, `systemSizes` (Task 1)
- Produces, in `src/types.ts`: `export type Hill = { id: string; group: string; x: number; y: number; footprint: number; height: number } & Size` — `footprint` is a radius in layout units from the exact code lines; `height` is in `[0, 1]`: `sqrt(branchPoints) / sqrt(max branchPoints in the guide)` (0 when the guide has no branch points)
- Produces, in `src/layout.ts`:
  - `export function sizeBucket(codeLines: number): number` — `codeLines < 1 ? 0 : 1 + Math.floor(Math.log2(codeLines))`
  - `export function footprintRadius(codeLines: number): number` — `16 + 2.3 * Math.sqrt(codeLines)`
  - `export function layoutHills(guide: Guide, sizes: Map<string, Size>): Hill[]` — in guide order, one per system
- Produces, in the page data: `map.hills: Hill[]` (and `map.sizes` is removed; update Task 1's tests to read sizes from `map.hills`)

Layout rules (the algorithm the tests cannot pin; constants are the builder's):
- Group anchors on an ellipse (radii 340 × 240) in `groups` order; a system whose `group` is unknown joins a fallback group placed last.
- Each system starts at its anchor plus jitter from a PRNG (mulberry32) seeded by an FNV-1a hash of its own id, so adding a system does not reseed the others.
- 700 relaxation steps with a linearly falling alpha: springs along each connected pair (rest length = sum of collision radii + 36 within a group, + 150 across groups), cohesion toward the group centroid, collision, and a weak pull toward the origin.
- Collision radius is `footprintRadius(2 ** sizeBucket(codeLines))`, never the exact size; minimum centre distance = 0.8 × the sum of collision radii + 30 within a group, 1.15 × the sum + 120 across groups.
- Round coordinates to 0.1 at the end, so float noise cannot differ between runs.

### Task 4: The map module and the page

**Files:**

**Interfaces:**
- Consumes: page data `map.hills`, `map.mapOnly`, `groups`, `systems[].connects`, `flows`
- Produces:
  - `src/render.ts`: `export const MAP_MARKER = "<!--TRAIL_MAP-->"`; `renderPage` replaces it (exactly one occurrence, else throw, like the data marker) with `templates/map.html` imported as text (the `.html` loader already exists)
  - `templates/map.html` defines `window.TrailMap = { mount: function (container, data, hooks) }` returning `{ select: function (id) {}, resize: function () {} }`; `hooks.onPick(id)` fires when a hill is clicked or tapped (the page then runs its own `select(id, true)`); `controller.select(id)` focuses that hill (lights its trails) without calling back
  - `templates/guide.html`: a `<!--TRAIL_MAP-->` marker before the page script; a Map | List switch above the left column; a new `<div id="trailmap">` beside the existing `#map` (which stays the list); `select()` also calls `trail.select(id)`; the search box, when one system matches, selects it on the map too

What the module draws and does is the spec's "What the map shows" section; these are the decisions it leaves to this task:
- Terrain: per group, a height field from Gaussians (spread 0.5 × `footprint`, peak = `height`), contoured by marching squares at levels `k × (1/9)` of the tallest hill; a separate unit-height footprint field per group gives the landmass outline at a fixed low level, so a flat hill still has land. A hill with `codeLines === 0` gets no rings and a "no code" sublabel.
- The page rotates the whole layout a quarter turn when the map area is taller than wide (by more than 10%) and the layout is wider than tall, or the reverse. Nothing else changes positions.
- Labels: greedy placement in screen pixels below, above, right, left; never over another label, a summit, a region name or the visible edge; priority: the focused hill (always shown), hills on the active route, then by `codeLines`; hidden when nothing fits.
- Route playback: the reading pause per stop is `min(5200, 1500 + 24 × text length)` ms; legs animate at about 0.32 px/ms, clamped to 500–2000 ms.
- View choice: default Map at ≥ 860px wide, else List; a reader's switch is saved in `localStorage` under `field-guide-view` inside `try/catch`. With `map.mapOnly`, the switch, the list, `#jobs-sec` and `#gloss-sec` are hidden.
- Hardening: before anything reads them, the page sets every missing array field on each system (`journey owns keyFiles models jobs switches connects rules checks watchOuts`) to `[]`, and missing `flows`/`glossary`/`groups` to `[]`.
- Every string from the data reaches the SVG through `textContent`; nothing from the data goes through `innerHTML` in the module.
- Legend: with nothing selected, the panel's overview starts with "How to read the map" (footprint = code lines, height = branch points, the one-line branch rule, regions, trails, routes).
- Accessibility: hills are `<g tabindex="0" role="button" aria-label="<name>, <codeLines> lines of code">`; Enter or Space picks. Reduced motion: route playback jumps from stop to stop instead of animating.
